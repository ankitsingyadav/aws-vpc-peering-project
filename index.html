Automated Provisioning

Infrastructure as Code (IaC)

Deploy the entire lab in minutes using HashiCorp Terraform or AWS CloudFormation.

terraform/main.tf 
# Terraform main.tf - AWS VPC Peering
terraform {
  required_version = ">= 1.3"
  required_providers {
    aws = { source = "hashicorp/aws", version = "~> 5.0" }
  }
}

provider "aws" {
  region = var.aws_region
  default_tags {
    tags = { Project = "EWB-VPC-Peering", Student = "Ankit Singh Yadav" }
  }
}

# VPC A (10.10.0.0/16)
resource "aws_vpc" "vpc_a" {
  cidr_block           = "10.10.0.0/16"
  enable_dns_hostnames = true
  tags                 = { Name = "ewb-vpc-a" }
}

# VPC B (10.20.0.0/16)
resource "aws_vpc" "vpc_b" {
  cidr_block           = "10.20.0.0/16"
  enable_dns_hostnames = true
  tags                 = { Name = "ewb-vpc-b" }
}

# Peering Connection (Auto-Accept in same account)
resource "aws_vpc_peering_connection" "peer" {
  vpc_id      = aws_vpc.vpc_a.id
  peer_vpc_id = aws_vpc.vpc_b.id
  auto_accept = true
  tags        = { Name = "ewb-a-b-peer" }
}

Evaluation Defense

Viva Voce Architectural Answers

Deep technical responses for the four critical questions outlined in the EWB student curriculum.

AWS VPC routing is strictly directional and explicit. While a peering connection establishes the network link, routing decisions are evaluated separately for every hop. When App-A (10.10.2.10) pings App-B (10.20.1.10), VPC A knows to route to the peering ID. App-B receives the packet and forms an ICMP Echo Reply destined for 10.10.2.10. Without a return route (10.10.0.0/16 → pcx-...) in VPC B's route table, VPC B has no target for the reply and drops the packet. Thus, return routing is mandatory for bidirectional connectivity.
When traffic moves across an internal VPC peering connection, it stays on the AWS private backbone. The Internet Gateway only translates public-to-private IPs for external internet egress. For inter-VPC traffic, packets retain their private source IP address (10.10.1.10). Security group ewb-sg-app-b inspects layer-3 headers; if it expected the bastion's public IP, the connection would be rejected because the arriving packet carries the private IP.
An "Active" peering status only confirms that the peering tunnel handshake was accepted. End-to-end IP reachability depends on four distinct layers: (1) Route tables directing destination CIDRs to the peering ID; (2) Stateful security groups permitting inbound ICMP Type 8 (Echo Request); (3) Subnet Network ACLs permitting transit in both directions; and (4) An active OS on the instance responding to ICMP. Peering is the link; routing and security rules govern packet transit.
No. AWS VPC Peering is strictly non-transitive and does not support edge routing. Traffic cannot enter a VPC via a peering connection and exit through an attached Internet Gateway, NAT Gateway, VPN, or Direct Connect. To provide internet access to VPC B, an independent gateway or AWS Transit Gateway must be deployed.
